# 센터 기반 상거래·통합 물류 개편 기준

상태: 현재 구현 기준

## 용어와 경계

- 센터, 매장, `Store`는 같은 보안 경계를 뜻한다.
- 운영자는 매장 사장이고 직원은 그 매장에 부여된 세부 권한만 사용한다.
- 통합 물류 그룹은 결제 이후의 준비·포장·배송 대행과 배송비 통합만 허용한다. 상품, 회원, 매출, 정산 권한은 공유하지 않는다.
- 소유자 권한과 운영자 권한은 분리하며, 소유자의 운영자 기능은 선택 매장과 만료되는 서버 범위가 있어야 한다.

## 주문과 배송

- 여러 매장 상품은 주문·수동 계좌이체 한 건으로 결제할 수 있다.
- 주문 시 배송 단위를 `store` 또는 `fulfillment_group`으로 나누고 정책을 불변 스냅샷으로 저장한다.
- 배송 단위마다 배송비 한 번, 배송 요청 하나, 송장 하나를 사용한다.
- 연결되지 않은 매장끼리는 합포장·배송 요청·송장을 공유하지 않는다.
- 상품 매출은 원판매 매장, 그룹 배송비는 주문 스냅샷의 대표 정산 매장에 귀속한다.

## 결제와 역사

- 실행 가능한 결제 수단은 소유자가 확인하는 수동 계좌이체뿐이다.
- PortOne 패키지, UI, 공개 API, 서버 분기와 DB 실행 권한은 폐기한다.
- 이미 적용된 마이그레이션과 법적·회계적 이력은 수정하거나 삭제하지 않는다. 과거 결제 식별자는 감사용 읽기 전용으로만 보존한다.
- `inventory_shipments`는 신규 배송 사실의 유일한 writer다. 구형 중앙 물류 모델은 활성 호출자를 제거하고 실행 권한을 회수하며, 검증된 고객 호환 읽기만 격리한다.

## 변경 규칙

- 스키마 변경은 추가형 순방향 마이그레이션으로만 수행한다.
- 새 `public` 테이블과 RPC는 명시적 `GRANT`와 RLS를 함께 정의한다.
- 모든 mutation은 매장 소속, 세부 권한, CAS, 멱등 키와 append-only 감사를 사용한다.
- 운영 데이터 전환은 자동 매핑, 수동 검토, 역사 보존으로 분류하며 통합 물류 그룹을 추정하지 않는다.
- 운영 적용 전 관련 없는 주문·환불·배송 예외 이력이 발견되면 변경을 중단한다.
