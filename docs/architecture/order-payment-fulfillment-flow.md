# 주문·결제·매장 출고 흐름

## 고객 정상 흐름

```text
여러 매장 상품 선택
→ 통합 주문 또는 낙찰품 결제 1건
→ 입금자명 입력과 공용 계좌 1회 입금
→ 운영자 입금 확인
→ 상품별 고객 보관 권리 생성
→ 원등록 매장이 상품 준비·보관
→ 고객이 여러 매장 보관 상품을 골라 배송 요청 1건 생성
→ 각 원등록 매장이 자기 상품 출고 완료
→ 합포장·송장 1개 등록
→ 상품 발송
→ 송장 등록 7일 후 배송 완료
```

## 결제

- 주문과 경매 낙찰품은 고객이 한 번에 결제한다.
- 택배비 포함 결제가 기본이며 상품 합계, 택배비, 총 결제 금액을 분리해 표시한다.
- 운영자는 입금액과 입금자명을 불변 원장에 기록한다.
- 누적 유효 입금액이 예정액과 일치할 때만 결제를 확정한다.
- 확인 취소와 금액 정정은 기존 기록을 덮지 않고 역원장과 사유를 추가한다.

## 보관

- 결제 확정은 상품별 `CustomerInventoryItem`을 정확히 한 번 생성한다.
- 상품은 원등록 매장이 직접 보관하며 별도 센터 입고 단계가 없다.
- 소형은 14일, 대형은 7일 보관한다.
- 배송 신청에 포함된 상품은 즉시 선택 가능한 보관 목록에서 제외한다.

## 배송 요청

- 배송 이용권이 있어야 요청할 수 있다.
- 고객은 서로 다른 매장의 상품을 한 요청에 선택할 수 있다.
- 요청 생성 시 주소와 상품 manifest를 서버가 검증하고 같은 상품의 중복 요청을 막는다.
- 모든 매장은 요청 전체의 최소 정보와 상품 사진을 볼 수 있지만 자기 매장 상품만 출고 처리한다.
- 모든 매장 작업 완료, 유효 주소, 배송비 또는 이용권, 미해결 예외 없음이 확인된 뒤 포장·송장을 등록한다.
- 송장 삭제는 포장 단계로 되돌린다. 고객에게는 발송 준비 중, 상품 발송, 배송 완료만 보여 준다.

## PortOne 경계

활성 체크아웃은 수동 계좌이체만 호출한다. PortOne 준비·동기화·웹훅 코드는 재검토 전까지 비활성 어댑터로 보존하며 공개 UI와 API에서 실행하지 않는다.
