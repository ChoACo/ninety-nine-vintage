# 주문·결제·매장 출고 흐름

## 고객 정상 흐름

```text
여러 매장 상품 선택
→ 통합 주문 또는 낙찰품 결제 1건
→ 입금자명 입력과 공용 계좌 1회 입금
→ 소유자 입금 확인
→ 상품별 고객 보관 권리 생성
→ 원등록 매장이 상품 준비·보관
→ 주문 시 단독 매장 또는 통합 물류 그룹별 배송 단위 생성
→ 배송 단위별 배송비·배송 요청 1건 생성
→ 원등록 센터 또는 같은 통합 물류 그룹 센터가 상품 준비 완료
→ 배송 단위별 포장·송장 1건 등록
→ 상품 발송
→ 송장 등록 7일 후 배송 완료
```

## 결제

- 주문과 경매 낙찰품은 고객이 한 번에 결제한다.
- 택배비 포함 결제가 기본이며 상품 합계, 택배비, 총 결제 금액을 분리해 표시한다.
- 소유자는 입금액과 입금자명을 불변 원장에 기록한다.
- 누적 유효 입금액이 예정액과 일치할 때만 결제를 확정한다.
- 확인 취소와 금액 정정은 기존 기록을 덮지 않고 역원장과 사유를 추가한다.

## 보관

- 결제 확정은 상품별 `CustomerInventoryItem`을 정확히 한 번 생성한다.
- 상품은 원등록 매장이 직접 보관하며 별도 센터 입고 단계가 없다.
- 소형은 14일, 대형은 7일 보관한다.
- 배송 신청에 포함된 상품은 즉시 선택 가능한 보관 목록에서 제외한다.

## 배송 요청

- 배송 이용권이 있어야 요청할 수 있다.
- 고객의 주문은 여러 매장 상품을 포함할 수 있지만 서로 다른 배송 단위의 상품을 한 배송 요청으로 합칠 수 없다.
- 요청 생성 시 주소와 상품 manifest를 서버가 검증하고 같은 상품의 중복 요청을 막는다.
- 출고 그룹 밖 센터는 요청을 볼 수 없다. 같은 그룹 센터는 최소 출고 정보만 보고 서로 대신 처리할 수 있다.
- 배송비는 기본적으로 센터마다 청구한다. 소유자가 그룹당 1회 청구를 선택하면 그룹 대표 정산센터와 금액을 주문에 스냅샷으로 고정한다.
- 해당 배송 단위의 모든 상품 준비 완료, 유효 주소, 확정 배송비, 미해결 예외·활성 취소 요청 없음이 확인된 뒤 포장·송장을 등록한다.
- 송장 삭제는 포장 단계로 되돌린다. 고객에게는 발송 준비 중, 상품 발송, 배송 완료만 보여 준다.

## 결제 실행 경계

활성 체크아웃은 소유자가 확인하는 수동 계좌이체만 사용한다. PortOne 준비·동기화·웹훅·브라우저 결제와 런타임 전환 경로는 폐기하며, 과거 결제 식별자는 감사용 읽기 전용 이력으로만 남긴다.
