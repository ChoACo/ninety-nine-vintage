# 제품·운영 원칙

상태: 기준 문서
적용 범위: NINETY-NINE VINTAGE의 제품, 데이터, API, 운영 화면

## 제품 정의

NINETY-NINE VINTAGE는 단일 소유자가 결제와 정책을 통제하면서 복수 운영자가 센터별로 판매하는 멀티센터 빈티지 커머스다. 센터는 상품·회원·매출·정산의 독립 보안 경계이며, 출고 그룹은 물류 협업 권한만 확장한다.

## 변경할 수 없는 운영 원칙

1. 모든 상품은 원 판매센터 하나에 귀속되고 매출·정산 귀속은 바뀌지 않는다.
2. 소유자는 운영자 입점, 센터 배정, 회원제, 정산계좌와 출고 그룹을 승인한다.
3. 운영자와 권한 있는 직원은 자기 센터 상품만 등록·공개·수정한다.
4. 고객 장바구니·주문·낙찰 결제는 매장별로 나누지 않고 한 번에 처리한다.
5. 공용 입금 대기열 조회와 결제 확인은 소유자만 수행한다.
6. 결제 확정은 상품별 고객 보관 권리를 정확히 한 번 만든다.
7. 상품의 준비·보관·발송 책임은 원등록 매장에 있다. 별도 센터 입고나 매장 간 이동을 요구하지 않는다.
8. 주문은 여러 매장 상품을 한 번에 결제할 수 있지만 배송 단위는 단독 매장 또는 활성 통합 물류 그룹별로 분리한다.
9. 기본적으로 원 센터가 출고하며, 같은 활성 출고 그룹의 운영자는 서로 대신 처리할 수 있다.
10. 한 상품은 진행 중인 배송 단위 하나에만 포함할 수 있고 신청 후 보관 상품 목록에서 제외한다.
11. 배송비·배송 요청·송장은 배송 단위마다 하나씩 생성한다. 연결되지 않은 매장끼리는 합포장이나 송장을 공유하지 않는다.
12. 고객에게는 내부 매장 처리 단계를 숨기고 발송 준비, 상품 발송, 배송 완료 상태만 제공한다.

## 결제 원칙

- 활성 결제 수단은 수동 계좌이체뿐이다.
- PortOne 브라우저·서버 의존성, 공개 API, UI, 런타임 분기와 실행 가능한 DB 함수는 폐기한다. 과거 결제 식별자는 감사에 필요한 최소 범위에서 읽기 전용으로만 보존한다.
- 금액, 재고 잠금, 입금 완료, 보관 권리 생성은 서버와 데이터베이스가 결정한다.
- 입금 확인·취소·금액 정정은 CAS와 멱등 키를 사용하고 행위자·시각·금액·입금자명·사유를 감사 기록으로 남긴다.
- 상품 매출은 원 센터에 귀속한다. 배송비는 센터별 또는 출고 그룹별 주문 스냅샷에 따라 지정된 정산센터에 귀속한다.

## 배송 불변식

- 배송 단위의 상품 목록은 생성 후 임의로 바꾸지 않는 manifest다.
- 여러 주문과 구매 유형을 합칠 수 있지만 동일 상품을 중복 신청할 수 없다.
- 배송 이용권이 없으면 배송 요청을 만들 수 없다.
- 주소, 배송비, 미해결 예외, 활성 취소 요청과 해당 배송 단위의 모든 상품 준비 완료가 확인되기 전에는 포장·송장을 만들 수 없다.
- 송장 삭제는 포장 단계로 되돌리고, 송장 등록 7일 후 배송 완료로 전환하며 최소 기록은 30일 보존한다.

새 기능이 이 문서와 충돌하면 코드보다 먼저 정책 결정을 갱신한다.
