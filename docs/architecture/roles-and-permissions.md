# 역할과 권한

## 역할

- `owner`: 전체 매장, 운영자, 직원, 회원, 전역 설정과 감사 기록을 관리한다.
- `operator`: 명시적으로 배정된 센터만 관리한다. 다른 운영자 상품은 구매할 수 있지만 자기 센터 상품은 구매·입찰할 수 없다.
- `employee`: 상위 운영자와 활성 매장 소속을 통해 부여된 세부 권한만 사용한다.
- `member` 및 고객 등급: 상품 조회, 통합 결제, 보관 상품 선택, 배송 요청, 자기 기록과 채팅만 사용한다.

## 권한 행렬

| 작업 | owner | operator | employee | member |
|---|---:|---:|---:|---:|
| 매장·인력 배치 | O | 자기 직원 | 권한 시 | X |
| 자기 매장 상품 관리 | O | O | 권한 시 | X |
| 다른 매장 상품 수정 | O | X | X | X |
| 공용 입금 조회·확인 | O | X | X | X |
| 자기 매장 상품 보관·출고 | O | O | 권한 시 | X |
| 출고 그룹 배송 요청 조회 | O | 그룹 내 | 권한 시 | X |
| 포장·송장 등록 | O | O | 권한 시 | X |
| 자기 주문·보관·배송 조회 | 운영 지원 | 운영 지원 | 운영 지원 | O |
| 전역 계좌·결제 모드 변경 | O | X | X | X |

## 강제 규칙

- 역할명만으로 매장 접근을 허용하지 않는다. API, RPC, RLS가 활성 `store_memberships`와 세부 권한을 검사한다.
- 출고 그룹은 `prepare_orders`, `receive_at_center`, `create_shipments`만 확장하고 상품·회원·매출·정산 권한은 확장하지 않는다.
- `stores.operator_id`와 `reports_to_operator_id`는 신원·보고 관계이며, 실제 상품 접근 범위는 매장 소속이 기준이다.
- 운영자 채팅은 배정 매장 회원 대화와 자기 직원 내부 대화만 허용한다. 직원은 상위 운영자의 활성 매장 회원 대화와 자기 내부 대화만 허용한다.
- 공용 입금·배송 큐에는 업무에 필요한 최소 회원·상품·금액 정보만 투영한다.
- UI 버튼 숨김은 보안 경계가 아니다. 모든 mutation은 서버 인증, RLS, CAS, 멱등성을 함께 적용한다.
- owner의 3분 회원 모드는 저장된 역할을 변경하지 않는 일시 세션이며 서버가 만료를 강제한다.
- 로컬 테스트 계정은 일반 개발과 운영에서 항상 비활성화한다.
- PortOne 활성화 권한은 현재 어떤 역할에도 없다. 서버 기능 플래그가 고정 비활성 상태다.
