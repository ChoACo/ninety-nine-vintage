# 판매센터·센터몰·상품 피드 UX 재구성 계획

작성일: 2026-08-14  
대상 브랜치: `codex/center-commerce-rebuild`

## 목표

- 판매센터의 매출과 정산 정보를 현재 선택한 매장으로 엄격히 제한한다.
- 구매자 정보와 상품 정보를 거래 원장 항목에서 바로 식별할 수 있게 한다.
- 관리자 시스템 화면과 채팅을 각각 독립된 목적의 화면으로 분리한다.
- 전체 상품 피드는 모든 매장의 상품을 보여주되 등록일별로 최근 상품만 선택할 수 있게 한다.
- 센터몰은 센터 소개, 경매, 즉시구매, 문의를 한 매장 안에서 탐색하는 독립 상점 구조로 만든다.

## 확인된 원인

### 판매센터 매출에 다른 매장이 노출되는 이유

`/api/admin/operator/revenue`는 `authenticateOperatorStoreRequest()`로 현재 선택 매장을 확인하지만 `get_store_financial_report(p_from, p_to)` 호출에는 선택 매장 ID가 들어가지 않는다. 해당 RPC는 `is_owner()` 또는 `has_store_permission(store_id, 'view_reports')`가 참인 모든 매장을 집계하므로, 여러 매장 권한을 가진 소유자·운영자에게 다른 매장도 반환된다.

조치 원칙:

1. DB 재무 함수가 현재 활성 매장 범위를 직접 요구한다.
2. API가 결과의 `storeId`를 `selectedStoreId`와 다시 대조한다.
3. 상품·구매자 보강 조회도 같은 매장 ID로 제한한다.

### 관리자 시스템 탭이 운영 현황으로 이동하는 이유

`/admin/owner/site-status/page.tsx`가 실제 시스템 화면을 렌더링하지 않고 `redirect('/admin/owner')`만 수행한다. 시스템 편집 패널은 현재 `OwnerDashboard` 안에 포함돼 있어 별도 탭이 존재하지만 별도 페이지는 존재하지 않는 구조다.

조치 원칙: 시스템 탭에서 `OwnerSiteStatusPanel`, 저장공간, 토큰 사용량 등 시스템 전용 도구를 직접 렌더링하고 운영 현황과 분리한다.

### 채팅 아이콘이 회원 채팅으로 이동하는 이유

`ChatNotificationProvider`는 `/api/chat/unread`가 반환한 역할별 최신 대화 URL을 아이콘 링크로 우선 사용한다. 소유자·운영자는 이 API가 `/admin/operator/chat`을 반환하기 때문에 일반 채팅 진입도 회원 채팅 업무 화면으로 연결된다.

조치 원칙: 상단 채팅 아이콘은 독립 채팅 허브로 고정하고, 읽지 않은 대화는 허브 안에서 역할별 받은 편지함으로 분기한다. 업무센터의 회원 채팅 메뉴는 기존 전문 콘솔로 유지한다.

## 정보 구조

### 판매센터

1. 오늘의 할 일
2. 상품 관리
3. 주문·낙찰
4. 준비·배송
5. 회원 채팅
6. 매출·정산
7. 매장 설정

매출·정산의 기본 카드:

- 선택 기간 총매출
- 오늘 매출
- 이번 주 매출
- 취소·환불
- 순매출
- 다음 정산 예정액
- 지급 완료액
- 다음 정산일

거래 항목은 시각, 구분, 금액, 상품 이미지·상품명, 구매자 표시명으로 구성한다. 전체 UUID를 기본 표에 노출하지 않는다.

### 독립 채팅

- 구매 문의
- 상품 문의
- 판매센터 회원 상담
- 직원 내부 상담
- 읽지 않은 대화

상단 아이콘은 항상 독립 채팅 허브로 이동한다. 특정 새 메시지가 있어도 허브가 대화 선택 상태를 복원한다.

### 전체 경매·즉시구매

- 기본 범위는 모든 센터
- 상단에 센터몰 선택 영역 제공
- 기본 날짜는 KST 당일
- 날짜 선택 시 해당 날짜에 공개된 상품만 표시
- `전체 날짜`는 명시적으로 선택한 경우에만 과거 상품까지 표시
- 전체 피드의 매장·상품 순서는 날짜 안에서 안정적인 랜덤 순서를 유지

### 센터몰

- 센터 정보
- 진행 중 경매
- 즉시구매
- 문의하기
- 날짜 선택

센터몰의 경매와 즉시구매는 KST 당일이 기본이며 선택한 등록일의 상품만 표시한다. 센터 문의는 해당 `storeId`를 포함해 독립 채팅으로 연결한다.

## NEW 표시 규칙

- 기준: `publish_at`이 현재 KST 날짜와 같은 상품
- 위치: 상품 이미지 왼쪽 상단의 작은 `NEW` 배지
- 판매 유형 배지와 겹치지 않게 세로로 배치
- 서버와 브라우저 모두 같은 KST 날짜 계산 함수를 사용

## 구현 순서와 완료 조건

1. 매출 DB/API를 선택 매장 범위로 제한하고 상세 정보를 보강한다.
2. 관리자 시스템 페이지를 독립시킨다.
3. 독립 채팅 허브와 상단 아이콘 고정 진입을 구현한다.
4. 전체 피드와 센터몰에 KST 날짜 필터와 센터 선택을 적용한다.
5. 모든 상품 카드에 NEW 배지를 적용한다.
6. RLS·RPC 권한, 쿼리 범위, 테스트, 린트, 빌드를 검증한다.
7. 작업 브랜치를 운영 배포하고 PC·모바일·소유자·운영자 카나리를 수행한다.

## 보안·성능 경계

- 매출·구매자 정보는 서비스 역할 전체 조회 결과를 그대로 반환하지 않는다.
- 구매자 정보는 선택 매장의 확정 거래에 연결된 최소 필드만 반환한다.
- 매출 함수는 활성 선택 매장과 `view_reports` 권한을 모두 확인한다.
- 날짜 조건은 `publish_at >= start` 및 `< next_day` 형태로 인덱스를 사용할 수 있게 한다.
- DB 함수는 명시적 `search_path`, 최소 GRANT, 호출자 검사 원칙을 유지한다.

## 2026-08-14 센터몰 2차 고도화

- 센터몰을 소개 페이지가 아닌 독립 판매 상점 홈으로 구성한다.
- 상점 히어로, 대표 상품, 선택일 판매 지표, 신상품 등록일, 경매관, 즉시구매관, 판매완료, 센터 소개와 상담 안내 순서로 구매 흐름을 만든다.
- 날짜 목록은 고정 달력으로 만들지 않는다. 해당 센터의 공개·판매 중 상품이 실제 존재하는 KST 등록일만 노출한다.
- 요청 날짜에 상품이 없으면 오늘 상품이 있을 때 오늘로, 그렇지 않으면 가장 최근 상품 등록일로 보정한다.
- 공개 상품이 하나도 없으면 빈 날짜 버튼 대신 다음 상품 준비 상태를 보여준다.
